# MLP audit — 2026-09-09

## Verdict

The existing results do not establish a clean eight-core, end-to-end MLP
speedup on the configuration used for the recent FlashAttention search.
There are two distinct benchmark families; their names should not be conflated.
No new performance measurements were made by this audit.

## Full SwiGLU FFN

Artifacts: `results/ai_workloads/ffn_cache_t64_d512_f1536`,
`ffn_spm_t64_d512_f1536`, and `ffn_spm_matched_swiglu_t64_d512_f1536`.
These run T64, D512, F1536, KC256, MC128 at VL16 on **one core**.
The recorded command is the same mutable `ffn_spm` path for both SPM results;
current source cannot by itself prove the exact provenance of both old ELFs.

- The source computes three GEMMs plus SwiGLU, so this is a complete FFN.
- Cache uses private-L2 TreePLRU; SPM uses LRU. Policy is not matched.
- Both top-level drivers time and print operations inside the marked region.
  `gemm_knm_prepacked` also has explicitly always-on per-call timing/printing,
  even with a null timing-output pointer. SPM GEMM contains analogous timers.
  This is not merely the FA null-timer bug; all timed/printed paths need review.
- Every result contains just one statistics dump. Its `simTicks` equals the
  final process exit tick (13,870,154,000 baseline; 11,443,514,400 matched-SwiGLU
  SPM). These dumps include initialization and additional warm execution, not
  an isolated FFN ROI. `m5_work_begin/end` alone do not replace explicit
  reset/dump boundaries in these runs.
- Logs contain no output checksum, finite check, numerical reference or PASS.
  Normal exit therefore does not establish numerical correctness.
- Cache weight prepacking occurs before its marked region, whereas SPM stages
  row-major weights inside GEMM. This can be a valid amortized-weight scenario,
  but is not an end-to-end preparation-inclusive comparison. Both cases need
  explicit reporting. Source SE cache-flush helpers are no-ops, so the printed
  “cold/flushed to DRAM” label is not evidence of a controlled cold state.

Relevant sources are the micro tree's `kernels/llama_bench/08_ffn_swiglu.cpp`,
`kernels_sve.hpp`, `common.hpp`, and corresponding `llama_bench_spm` files.
The matched-SwiGLU name indicates an earlier activation-alignment attempt;
it does not repair the policy, ROI, provenance or correctness issues above.

## Eight-core diffusion “FFN” operator

`run_real_operators.sh` selects `diffusion_gelu_residual` with M128/M512 and
K=N=768. The shared driver implements **one GEMM + bias + GELU + residual**.
There is no second FFN projection and no three-GEMM SwiGLU chain.

| M | Historical cache ROI, us | Historical SPM ROI, us | Ratio |
|---|---:|---:|---:|
| 128 | 545.0128 | 416.0932 | 1.3098x |
| 512 | 1266.6660 | 1132.8852 | 1.1181x |

These are genuine isolated-ROI operator measurements, but **not yet clean
CacheFlex gains**: baseline private L2 uses TreePLRU and SPM uses LRU.
Both report PASS with zero maximum error. Their reference combines host GEMM
output with the same guest activation helper, so the activation implementation
is not independently numerically validated. Driver phase timers are conditional
on `CACHEFLEX_PHASE_PROFILE`; there is no equivalent unconditional timer block
in the normal source path. Recorded numerical checks occur outside the ROI.

## Core mismatch with clean FA

The earlier MLP/operator runners explicitly set selected FU counts to two.
Clean FA uses the inherited defaults. The actual recorded difference is:

| Parameter | Earlier MLP/operator | Clean FA |
|---|---:|---:|
| SPM load ports | 1 | 2 |
| FUList00 count | 2 | 6 |
| FUList02 count | 2 | 4 |
| FUList05 count | 2 | 4 |
| FUList07 count | 2 | 1 |
| FUList09 count | 2 | 4 |

These are configuration-array identifiers, not inferred FU classifications.
They prohibit directly combining the old operator speedups with the new FA
timings to predict model latency. Baseline/SPM matching *within* an old pair
does not make that pair comparable to a different FA core configuration.

## Required clean experiment

Use a shared eight-core full-MLP driver on the exact clean-FA core/cache policy:
three projections plus identical SwiGLU, identical weights/inputs/precision,
explicit full-chain stats reset/dump, no internal clocks or prints, and checks
on every output against an independent reference. Freeze simulator/ELFs and
separate one-time weight preparation from amortized inference. Run both
architectures and retain their independently tuned kernels. A policy-only
rerun of the projection proxy would not establish this full-MLP result.

Reproduce the recorded-config portion of the audit with:
`python3 benchmarks/ai_workloads/audit_mlp.py`.
