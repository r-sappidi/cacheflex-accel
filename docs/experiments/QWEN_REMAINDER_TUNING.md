## Workload and boundaries

vocabulary151936, epsilon1e-6, rotary theta1e6. Existing saved model config is
authoritative. Synthetic FP16 tensors, FP32 reductions; not BF16 checkpoint
inference. Operator semantics checked against the pinned official implementation:
https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen2/modeling_qwen2.py

| Operator | Shape/boundary | Eventual model multiplicity |
|---|---|---:|
| RMSNorm | T x896, FP32 square/reduce/normalize; FP16 rounding before gamma multiplication |48|
| Residual | two T x896 arrays, FP16 add |48|
| RoPE application | Q14 and K2 head-major arrays, split-half rotation, eager FP16 product/add rounding; V untouched |24|

| Final normalization | full T x896, after decoder stack |1|
| Vocabulary projection | last hidden vector x native151936 x896 tied-weight layout; true GEMV, no padded rows or free transpose |1|

Last-position logits is an explicit prefill-for-generation policy. Vocabulary
GEMV is context-independent and measured once, not rerun for each T. All-position
logits, token sampling, decode, KV allocation/copy into a persistent generation
cache, tokenizer and framework dispatch are outside this initial component scope.
Input creation/checkpoint loading is outside ROI for every arm, like current
component drivers. Table generation has its own measured ROI; its input inverse
frequencies are model constants, and application receives the generated layout.
Application's standalone table input is independently generated by the oracle;
this is not yet an integrated producer/consumer timing measurement.

Embedding and logits both use the native tied-weight matrix layout, with no
duplicated/prepacked matrix charged to only one architecture. Their standalone
synthetic weight values differ; integrated tied-weight execution remains a later
validation. Final normalization processes all T rows, consistent with the pinned
model before last-position logit slicing.

## Analytical candidate selection

Use actual 2048-bit SVE, FP16 storage, FP32 lane arithmetic on the same eight-core
platform. Continuous row intervals divide across cores, preserving head-major
rotary addressing. Each SIMD FP32 vector has64 lanes; each logits dot accumulates
14 chunks and reduces its64 lanes. Candidate logits blocks1/2/4 have1/2/4 live
accumulator vectors, reuse the same hidden vector, and preserve each dot's order.
The full weights occupy272269312 bytes, far beyond private SPM. Each weight is
consumed once; arithmetic intensity is about1 FLOP/weight byte. Staging all
weights through SPM cannot eliminate this compulsory stream, so the initial
SPM-platform implementation deliberately uses the coherent SVE fallback.

Other operators select row blocks1/8/32: an unblocked control, a small scheduling
block, and a block spanning57344 input bytes for896-wide FP16 rows. Norm reuses a
1792-byte gamma and an individual1792-byte row, already small enough for L1;
residual and embedding have no arithmetic reuse; rotary reuses128 table bytes
across16 heads per token. These are exact working-set/count observations, not
predicted speedups. No arbitrary SPM staging penalty is imposed. Both arms run
the SAME ELF, differing only in the established eligible-SPM-way setting0/6.
There are zero SPM copy/reduction commands. This measures a legitimate common
implementation on each platform, not a demonstrated SPM arithmetic offload.

Equal three-candidate budgets per operator/backend at T1024. Select each backend
independently on first complete ROI, then transfer its winner plus block1 control
to T2048/T4096. Retain all null/regressive results. No long-context full-model
projection until FFN/projection coverage extends too. A future genuinely different
reuse/fusion strategy requires its own matched experiment, not relabeling this
fallback as exhaustively optimized SPM.

## Gates, acceptance and decision

T1/V17 tail/empty-core gates, then all choices/arms at T25/V263; full-output oracle,
exact backend/block peer bits, export hash versus guest hash, config whitelist,
zero-copy/reduction counts, bounded LSQ/global-resource checks precede targets.
Host tests independently exercise shape/layout, cancellation, corruption rejection,
configuration mutation rejection, and resource admission. Guest output validation
is after ROI. Every case has two calls: first full invocation is the objective;
second is a repeat diagnostic, not a stable warm median. Timed worker barriers,
stores and table trig are included. A failure stops downstream/peers.

NumPy float64 independently checks every result. Residual, embedding and rotary
require exact FP16 oracle bits. Reduction/tree and cross-ISA libm rounding may
cross FP16 midpoints: logits bound2e-5+0.001*abs(reference), table generation
2e-6+0.001*abs(reference), normalization2e-6+0.002*abs(reference) for its two
roundings. Exact bits across block/backend and across repeats remain mandatory.
These bounds are set before simulation, not adjusted to accept a failure.

Decision: lower complete first ROI versus block1, then strongest measured cache
versus private-platform implementation for that operator. No stall-sum attribution,
global-optimality claim, or fabricated L3 benefit. Model totals remain null until
at least one integrated layer checks arithmetic, layouts, cache/packing state and
the difference between measured integrated time and the component sum.
